# 中文代码注释规范

仓库内全部文本文件统一采用 **UTF-8（无 BOM）** 编码和 LF 换行；二进制网表不做编码转换。编辑器应遵循仓库根目录的 `.editorconfig`。

## 基本原则

1. 注释说明“为什么”和接口约束，避免逐字复述代码。
2. 模块名、信号名、协议名和数学符号保留英文，说明文字使用简体中文。
3. 不在源码中保留调试过程、版本回退过程或无法验证的结论。
4. 修改逻辑时同步更新相邻注释；过期注释视为缺陷。

## Verilog

手写 RTL 文件使用统一文件头：

```verilog
// =============================================================================
// 项目名称：2026 年全国大学生集成电路创新创业大赛国奖项目
// 作者：Ethereal
// 文件名称：example.v
// 主要模块：example
// 功能说明：说明该模块在数据通路中的职责。
// 维护说明：修改接口或时序时，请同步更新本文件注释和上层例化。
// =============================================================================
```

时序说明应明确时钟域、复位极性、有效电平和数据延迟。厂商生成 IP 的版权与许可注释必须原样保留。

文件头之后还必须提供正文内联注释：

- 模块声明前说明数据路径、控制路径和时序边界。
- 参数和端口组说明配置目的、方向和协议约束。
- 内部信号组说明其用于流水线、状态保存还是模块互连。
- 每个 `always` 过程说明时钟/复位方式或组合逻辑的完整赋值要求。
- `case` 分支说明状态、算法模式或控制字的选择依据。
- 连续赋值说明其为组合连线且不会增加寄存器延迟。
- 子模块例化说明该模块在当前数据通路中的具体职责。

统一使用 `[Ethereal注释]` 标识新增的正文导读和结构说明，方便与厂商生成注释区分。

## Python

- 模块开头使用 docstring 说明用途、输入输出和依赖硬件。
- 类与公开方法使用 docstring 说明职责；复杂分支在代码前说明设计原因。
- 常量按网络、图像和运行时状态分组，单位写入名称或注释。
